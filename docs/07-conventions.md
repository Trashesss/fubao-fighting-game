# 07. 규칙

## 코드

- TypeScript strict, `noUnusedLocals`/`noUnusedParameters`. 타입 검사가 깨진 채로 커밋하지 않는다 (`npm run build`).
- 순수 Three.js (래퍼 없음). 외부 3D 에셋·모델 파일을 쓰지 않는다 — 형상은 코드로 만든다 (D-03).
- **의존성 추가는 사용자에게 먼저 묻는다.** 서브디비전도 그래서 직접 구현했다.
- 주석은 한국어. "무엇"보다 **왜 그 값인지**(근거·실패했던 대안)를 적는다. 숫자 상수에는 출처(사진 랜드마크 / 해부 비례 / 사용자 결정)를 붙인다.
- 공용 코드와 캐릭터 코드를 나눈다:
  - `src/procedural/` 형상 도구 (서브디비전, 거리장·Surface Nets, 껍질 털), `src/animation/` 포즈 클립, `src/fighting/` 판정·프레임 데이터 — 캐릭터를 모른다.
  - `src/characters/<이름>/` 해부·케이지·뼈대·애니메이터·동작·명세(`spec/`).
  - `src/viewer/` 개발용 뷰어.

## 단위와 좌표

- 길이 m, 각도는 채널·설정에서 **도**, 내부 계산은 라디안 (`DEG`). 시간은 **60fps 프레임**.
- 모델 좌표 +Y 위, +Z 정면, +X 오른쪽. 캐릭터 해부 매개변수(부캉이 u, h, θ)는 [03-bukangi-model.md](03-bukangi-model.md#좌표와-매개변수).
  푸바오는 해부 좌우를 뼈 이름(`_L`/`_R`)에 쓰므로 **+X = 캐릭터의 왼쪽**으로 적는다 (앞을 보고 선 캐릭터에서 위 × 앞 = 왼쪽, [08](08-fubao-model.md#좌표)).
- 색: sRGB 값으로 적고 선형화해서 꼭짓점 색에 쓴다. 텍스처는 `colorSpace` 를 명시한다.

## 형상·동작 작업 규칙 (실패에서 나온 것)

1. 형상은 **설계 곡선·랜드마크·케이지 조절점**으로 고친다. 사진 픽셀·노이즈를 형상에 넣지 않는다 (D-07).
2. 함수를 smoothstep 으로 이어 붙이지 않는다. 곡률이 끊겨 구김이 된다.
3. 정체 디테일(아가미·입 등)은 맵으로, 노이즈 디테일은 넣지 않는다.
4. 형상과 자세를 따로 검증한다. 바인드 포즈(헤엄)는 사진과, 서 있는 자세는 사용자 피드백과 비교한다 (D-09).
5. 큰 굽힘은 구간으로 나눠 준다. 한 뼈에 몰지 않는다.
6. 고친 뒤 [05-quality-gates.md](05-quality-gates.md) 를 돌리고 수치와 함께 보고한다. 결함을 사용자가 먼저 찾게 하지 않는다.

## Git

- 커밋 메시지: `type: 한글로 간결하게` — type 은 `feat | fix | chore | docs | refactor | test | style | perf | build | ci`. 연관 이슈가 있으면 끝에 `(#123)`.
  여러 줄이면 첫 줄은 이 형식, 본문은 빈 줄 뒤에.
- 브랜치: 지금은 `main` 과 작업 브랜치 `캐릭터-디자인` 뿐이고 원격·`develop` 이 없다. 새 브랜치를 만들기 전에 `git fetch` 로 최신 상태와 `develop` 대비 히스토리를 확인하고,
  기존 브랜치명 패턴(`git branch -a`)을 따른다. 패턴이 정해져 있지 않으면 사용자에게 묻는다.
- 생성물(`out/`, `dist/`, `node_modules/`)은 커밋하지 않는다.

## 이미지 생성 (선택)

컨셉 아트는 sprite-gen(Codex 이미지 생성)으로 만들 계획이었다(D-05). 쓸 경우: 프롬프트에 캐릭터·게임 고유 이름을 넣지 않고, 새 종류의 이미지는 1장 먼저 확인한 뒤 나머지를 만든다.
